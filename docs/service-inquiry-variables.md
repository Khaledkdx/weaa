# متغيرات نموذج الخدمات اللوجستية

المسار: `/request-services`  
المكوّن: `frontend/src/serviceInquiryForm.tsx`  
قائمة الخدمات: `frontend/src/serviceInquiry.ts`

## المرحلة الأولى: البيانات

| الحقل الظاهر | اسم المتغير في النموذج | النوع | إلزامي | ملاحظات |
| --- | --- | --- | --- | --- |
| الاسم | `details.name` | نص | نعم | يُحفظ في `service_requests.name` |
| اسم الشركة | `details.company` | نص | لا | يُدمج في `service_requests.details` |
| رقم الجوال | `details.phone` | نص | نعم | يقبل `05xxxxxxxx` أو `+9665xxxxxxxx`، ويُحفظ بصيغة `+9665xxxxxxxx` في `service_requests.phone` |
| في أي مدينة | `details.city` | نص | نعم | يُدمج في `service_requests.details` |

## المرحلة الثانية: الخدمات

المتغير `selected` هو مصفوفة نصوص `string[]`. يجب اختيار خدمة واحدة على الأقل. أسماء الخدمات نفسها هي القيم المحفوظة حاليًا؛ لا توجد رموز API مستقلة لها.

### عقود تشغيلية

- `إدارة وتشغيل مشروع لوجستي`
- `عقد استشارات وتطوير`
- `عقد إنشاء وتأسيس مشروع لوجستي`
- `باقة كوادر`
- `عقد جلب أعمال وتشغيل مستودعات`
- `عقد إشراف وتطوير أعمال`

### الاستثمار

- `عقد الهرم الماسي` — استثمار المبالغ المالية في القطاع اللوجستي
- `عقد اتحاد الطبقة الأولى` — التشغيل الثلاثي في توفير المستودعات والمنتجات وتشغيلها ونقلها

الوصف المعروض تحت خيارات الاستثمار لا يُرسل كحقل منفصل. `inquiryDetails(details.company, details.city, selected)` يُنشئ النص المحفوظ في عمود `details` مع تقسيم الخدمات حسب الفئة.

## المرحلة الثالثة: المراجعة والإرسال

المرحلة الثالثة تعرض البيانات فقط، ولا تضيف متغيرات جديدة. عند الضغط على «إرسال الطلب»، تُضاف سطر جديد إلى جدول Supabase `public.service_requests` بالقيم التالية:

| عمود قاعدة البيانات | القيمة المرسلة |
| --- | --- |
| `service_slug` | `logistics-inquiry` |
| `service_title` | `طلب خدمات لوجستية` |
| `name` | `details.name.trim()` |
| `phone` | `+966` ثم الرقم السعودي الموحّد |
| `email` | نص فارغ `""`؛ النموذج لا يطلب بريد العميل |
| `details` | اسم الشركة والمدينة والخدمات المختارة كنص |
| `status` | `طلب جديد` |
| `created_at_label` | تاريخ محلي عربي كوسم إضافي |
| `id` | تولّده قاعدة البيانات تلقائيًا |
| `created_at` | تاريخ ووقت إنشاء الطلب؛ تضبطه قاعدة البيانات تلقائيًا |
| `updated_at` | تضبطه قاعدة البيانات تلقائيًا |

مثال لقيمة `details` عند اختيار خدمتين:

```text
اسم الشركة: شركة مثال

المدينة: جدة

عقود تشغيلية:
- باقة كوادر

الاستثمار:
- عقد الهرم الماسي
```

في لوحة الأدمن، تبويب «طلبات العملاء» يعرض التاريخ من `created_at`، وزر «تنزيل الشيت» ينزل CSV يحتوي التاريخ والاسم والجوال والبريد والخدمة والتفاصيل والحالة. لا يوجد ربط مباشر بـ Google Sheets في هذا التنفيذ.

## متغيرات حالة الواجهة

| المتغير | وظيفته |
| --- | --- |
| `step` | المرحلة الحالية: `0` بيانات، `1` خدمات، `2` مراجعة |
| `details` | حقول العميل الأربعة |
| `selected` | أسماء الخدمات المختارة |
| `pending` | منع إرسال الطلب مرتين أثناء الحفظ |
| `error` | رسالة التحقق أو خطأ الإرسال |
| `success` | إظهار تأكيد نجاح الإرسال |

إشعار البريد يُنفّذ من الدالة `supabase/functions/notify-service-request` بعد إضافة الطلب إلى قاعدة البيانات، وليس من المتصفح. إعداد المتغيرات السرية موضح في `docs/service-request-email.md`.
